# proxy-browser

Расширение для Firefox, которое проксирует не весь браузер, а только выбранные сайты — по хосту в адресной строке. Это утилита для точечной маршрутизации трафика через прокси, а не VPN и не инструмент для сокрытия трафика: причины направить конкретный сайт через конкретный прокси у пользователя могут быть любые (например: у сайта разные условия доступа/скорости в зависимости от маршрута, нужно развести разные сервисы по разным прокси, нужно проверить сайт «глазами» другой точки выхода и т.п.) — расширение не привязано к одной из них.

## Как это работает

1. Пользователь открывает нужный сайт, открывает popup расширения и добавляет текущий сайт в проксирование.
2. Расширение запоминает хост из адресной строки этой вкладки как правило (опционально — с префиксом пути) и позволяет назначить ему конкретный прокси-профиль (или использовать прокси по умолчанию).
3. Пока вкладка открыта на этом сайте (или на дочернем поддомене/пути, подходящем под правило), её запросы уходят через назначенный прокси; остальные вкладки идут напрямую.
4. Прочие хосты, замеченные у вкладки (CDN, аналитика, шрифты и т.п. — `webRequest`), используются только как подсказка в интерфейсе, а не как правило маршрутизации: такие домены часто общие для разных сайтов, и проксировать по ним означало бы задевать чужие сайты, использующие тот же CDN.

## Поддержка прокси

- Типы: `HTTPS`, `HTTP`, `SOCKS5`, `SOCKS4` (профиль хранит host/port/тип, опционально логин/пароль).
- `Xray/VLESS/VMESS/Trojan/Shadowsocks` напрямую не поддерживаются — такие клиенты обычно поднимают локальный `HTTP`/`SOCKS5` endpoint, на который и указывается правило.
- Несколько прокси-профилей одновременно, у каждого правила — свой прокси или прокси по умолчанию.
- Проверка прокси перед сохранением: расширение открывает скрытую вкладку через `api.ipify.org` и сравнивает IP с прямым запросом — так профиль с неверными данными не сохранится молча.

## Что умеет расширение

- хранить список прокси-профилей и список правил (сайт → прокси);
- включать/выключать конкретное правило без удаления;
- глобальный выключатель `Вкл/Выкл` для всего расширения;
- быстро добавить текущую вкладку в проксирование через popup;
- показывать, какой прокси реально применяется к текущей вкладке, и последнюю ошибку прокси, если она была.

## Ограничения

- расширение управляет только трафиком Firefox, не системным;
- сам прокси-сервер видит адреса назначения — это в целом свойство любого прокси, не что-то специфичное для этого расширения;
- правило матчится по хосту (и опционально префиксу пути) из адресной строки вкладки — не по произвольным сторонним доменам, замеченным на странице.

## Текущее состояние прототипа

- `manifest.json` для Firefox WebExtensions (Manifest V2, `browser.proxy` API);
- фоновый скрипт хранит конфигурацию (`browser.storage.local`) и применяет правила через `browser.proxy.onRequest`;
- popup с тремя вкладками: `Главная`, `Настройка`, `Прокси`;
- сценарий первого запуска без сохранённого прокси;
- сбор замеченных хостов активной вкладки как контекст/подсказка.

## Как запустить локально

1. Открыть Firefox → `about:debugging` → `This Firefox`.
2. `Load Temporary Add-on` → выбрать `manifest.json` из папки проекта.
3. Открыть нужный сайт → popup расширения → на вкладке `Прокси` сохранить прокси-профиль (при необходимости сделать его прокси по умолчанию).
4. На вкладке `Главная` включить `Вкл` и добавить текущий сайт в проксирование.

## Как собрать `.xpi`

Отдельный bundler не нужен — расширение написано как обычный WebExtension, сборка через `web-ext`:

```bash
npm install
npm run lint
npm run build
```

Готовый `.xpi` появится в `web-ext-artifacts/`. Для локальной разработки: `npm run run` — открывает Firefox с временно загруженным расширением.

## Публикация в Firefox Add-ons

1. Собрать `.xpi` через `npm run build`.
2. Загрузить его в [Firefox Add-ons Developer Hub](https://addons.mozilla.org/developers/) — подпись .xpi происходит на стороне Mozilla при загрузке, `web-ext build` только упаковывает.
3. Перед реальной публикацией заменить `browser_specific_settings.gecko.id` в `manifest.json` (сейчас `proxy-browser@evrkms`) на постоянный ID проекта, если он должен отличаться.

## Ближайшие улучшения

- более аккуратная фильтрация служебных и сторонних доменов в подсказке;
- редактирование уже сохранённых прокси-профилей;
- отдельное быстрое назначение прокси для текущего сайта прямо на главной вкладке;
- более явная индикация того, какой прокси реально выбран для текущей вкладки.
